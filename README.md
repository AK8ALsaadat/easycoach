# مساحة المدرب — easycoach

موقع SaaS عربي RTL لإدارة أعمال المدربين الشخصيين، بواجهات للكمبيوتر ومتجاوبة مع الجوال. Next.js 16.4.5 وTypeScript وTailwind وSupabase. بوابة المتدرب قابلة للتثبيت كتطبيق ويب (PWA) دون تطبيق متجر. لا AI أو بوابة دفع أو رسائل تلقائية أو مزامنة خارجية.

## التشغيل

يتطلب Node.js 24+ وnpm. تثبيت الحزم ثم المعاينة المحلية:

```bash
npm ci
cp .env.example .env.local
npm run dev
```

في Windows استخدم `Copy-Item .env.example .env.local`. اضبط `LOCAL_DB_PATH` لتشغيل `npm run dev` على PostgreSQL مضمّن (PGlite) على القرص، بنفس الهجرات وسياسات RLS. هذه القاعدة للتطوير فقط: بناء الإنتاج (`next build`) يحذف هذا الفرع بالكامل ولا يقرأ `LOCAL_DB_PATH`. لا توجد محاكاة للحفظ باستخدام localStorage. القاعدة في المسار المحدد بـ`LOCAL_DB_PATH` (مثل `./data/easycoach`). لا تفتح القاعدة نفسها من عمليتي Node متزامنتين.

المعاينة: **http://127.0.0.1:3200**. حسابات اصطناعية محلية: `coach@example.test` و`coach2@example.test` و`trainee@example.test`، وكلمة المرور `CoachPreview!2026`. وضع المعاينة المحلية يرفض المضيفين غير localhost/127.0.0.1 ولا يُنشر بهذا الوضع.

للاستخدام مع Supabase: احذف `LOCAL_DB_PATH`، واضبط URL ومفتاح Publishable و`APP_URL`، ثم ابنِ المشروع بنفس متغيرات البيئة. لا يوجد حساب تجريبي، ولا يُنشئ التطبيق حسابات المعاينة المحلية في Supabase.

## إضافات نوفمبر 2026

- **السعرات من الماكروز**: السعرات = بروتين×4 + كارب×4 + دهون×9، مع مفتاح تلقائي/يدوي يُحفظ مع الهدف (`calories_mode`)، تحذير فرق أكثر من 5٪، نسب التوزيع، والحساب العكسي من السعرات ونسب التوزيع. المنطق في `lib/macros.ts`، والقاعدة تتحقق من الوضع التلقائي.
- **بوابة المتدرب على الجوال وPWA**: ترتيب الأولوية وشريط تنقل سفلي، `app/manifest.ts`، أيقونات `public/icons` (تُولّد بـ`node scripts/generate-pwa-icons.mjs`)، و`public/sw.js`. يعمل الـService Worker في بناء الإنتاج فقط، ويخزّن ملفات البناء وآخر برنامج وخطة تغذية (`/api/offline-plan`) دون رسائل أو صور أو مسارات المدرب، مع صفحة `/offline` عربية وطابور أوزان دون اتصال.
- **أرشفة وحذف المتدرب**: الأرشفة افتراضية وقابلة للتراجع (`archived_at` و`archived_reason`)، والحذف النهائي للمؤرشفين فقط بعد كتابة الاسم، مع تصدير بيانات المتدرب (`/api/export?type=client-json|client-csv&client=…`).
- **تسمية القوالب**: اسم إجباري فريد لكل مدرب (2–60 حرفًا) بقيد في القاعدة، وسوم اختيارية (الهدف، المستوى، الأيام)، وترتيب «ابدأ من قالب…» حسب آخر استخدام.
- **موافقة صور التقدم**: جدول `client_consents` بنسخة الإشعار (`lib/photo-consent.ts` و`private.photo_consent_version()` يجب أن يتطابقا)، ويمنع الخادم أي رفع دون موافقة المتدرب نفسه.

كل هجرة جديدة لها سكربت تراجع يدوي في `supabase/rollbacks/`.

## الدخول بحساب Google

زر «الدخول بحساب Google» يظهر في وضع Supabase فقط عند `AUTH_GOOGLE_ENABLED=true`. قبل تفعيله: أنشئ OAuth Client (Web) في Google Cloud بعنوان الرجوع `https://trlgsugychocgwtnmzej.supabase.co/auth/v1/callback`، وأدخل Client ID وSecret في Supabase ← Authentication ← Providers ← Google، وتأكد أن `${APP_URL}/auth/callback` ضمن Redirect URLs. الحساب الجديد يأخذ نوع الحساب المختار قبل الدخول (مدرب افتراضيًا، ومتدرب عند الدخول من دعوة)، ولا يتغير نوع حساب موجود.

## ما نُفذ

بورتال إيزي كوتش: واجهة عربية بخط واضح وتخطيط متجاوب، ومكتبة 876 حركة بشرح عربي محلي. أزيلت رسومات العصا، وأضيف عرض تشريحي مرخص لتمرينين فقط وبديل محايد صريح للبقية. رفع فيديو مباشر أو QR، وجبات، هدف المرحلة والوزن اليومي، ورابط عميل محمي برمز يتحدث بعد النشر. [تفاصيل الاستخدام](docs/STUDIO.md) و[تقرير إعادة التصميم والتغطية](docs/REDESIGN.md).

- لوحة «اليوم»: عملاء بلا برنامج، برامج مرّ على نشرها 28 يومًا، باقات منتهية أو تنتهي خلال 7 أيام، ودفعات متبقية، محسوبة من القاعدة.
- إضافة وتعديل العملاء، بحث وتصفية، CSV/Excel مع اختيار الأعمدة ومعاينة الأخطاء والتكرار. الوضع الافتراضي يتخطى الموجود؛ الاستبدال يحتاج اختيارًا صريحًا. التحديث لا يبدل ارتباط الحساب أو برامجه. الاستيراد معاملة ذرّية، والورقة الأولى من Excel فقط؛ حد 2000 صف و5MB و20MB بعد فك الضغط.
- مكتبة تمارين خاصة: الاسم والشرح ورابط https اختياري. قوالب أيام وتمارين ومجموعات وعدات وراحة؛ النسخ يأخذ لقطة مستقلة للقالب والتمرين.
- محرر برنامج وتغذية بأهداف يحددها المدرب، وتوجيهات مستقلة لكل تمرين. حفظ مسودة تلقائي بعد 1.2 ثانية مع حالة حفظ وأخطاء وزر إعادة محاولة. النشر ينتج لقطة ثابتة؛ المتدرب يرى آخر برنامج منشور فقط. بوابة اليوم تعرض الخطة والتغذية والوزن وجدول المتابعة، وتدعم تسجيل الأداء الفعلي منفصلًا عن الوصفة.
- باقات بتاريخ بداية ونهاية منفصلين عن تاريخ الدفع، وتجديد مرتبط بالأصل، ومنع التداخل. تجميد شامل أول وآخر يوم مع قفل الصف ومفتاح عملية فريد، فلا يُطبَّق التمديد مرتين أو لفترات متداخلة.
- دفتر دفعات جزئية، ومنع الدفع الزائد والتكرار بالمعرّف والمرجع وبصمة السجل. الحركات ثابتة؛ التصحيح حركة عكس مرتبطة بالأصل وسبب موثق، ثم يمكن إضافة المبلغ الصحيح كحركة جديدة. **ليس فاتورة ضريبية**.
- روابط طلب انضمام 30 يومًا تحتاج موافقة، ودعوات 7 أيام أحادية الاستخدام ومخزنة كهاش. قبول الدعوة يتطلب نفس الإيميل الموثّق. إنشاء دعوة جديدة يلغي القديمة. تغيير إيميل العميل يلغي الربط والوصول والدعوات المعلّقة.
- بوابة حساب موثّق ورابط شخصي بلا تسجيل إلزامي: سر عشوائي في fragment يُستبدل بجلسة HttpOnly، مع إبطال الجلسات عند سحب الرابط أو تجديده وحد دائم لمحاولات فتحه. مسار PIN السابق يبقى متوافقًا. ربط الحساب اختياري بدعوة وإيميل موثّق ويحافظ على سجل المتدرب نفسه. مسودة واتساب يقرر المدرب إرسالها؛ لا يُرسل الخادم رسائل.
- تقدم خاص: وزن وقياسات اختيارية، وصور أمام/خلف/جانب بموافقة المتدرب، ومقارنة تاريخين واتجاهات فعلية وملاحظات ظاهرة للمتدرب منفصلة عن ملاحظات المدرب الخاصة. حفظ خادمي وتصحيح بإصدار متوقع ومنع تكرار المحاولة، وصور خاصة تُفحص وتُضغط وتزال بياناتها الوصفية على الخادم. للمدرب إضافة التحديثات ومراجعتها وتحديد تكرار الوزن والقياسات والصور لكل متدرب.

## قاعدة البيانات والمصادقة

المشروع المرتبط: `trlgsugychocgwtnmzej` / `easycoaching`، لندن `eu-west-2`. لا صلة ببيانات مشروع عونك.

```bash
npx supabase link --project-ref trlgsugychocgwtnmzej
npx supabase migration new descriptive_change
npx supabase db push --remote --dry-run
npx supabase db push --remote
npx supabase gen types typescript --remote > types/supabase.ts
npx supabase db lint --remote --level warning
```

كل تعديل للمخطط عبر هجرة جديدة. لا تعدّل هجرة مطبقة. طبقة الويب تستخدم Supabase HTTP RPC بمفتاح عام وجلسة المستخدم، وليس service role لقراءة بيانات المدربين. دور `coach_api` لا يقبل الدخول ولا يتجاوز RLS؛ يملك تنفيذ الكتابة المعتمدة فقط. الجداول تمنع الكتابة المباشرة من الدور authenticated. صلاحية التدريب لا تعتمد على إخفاء عناصر الواجهة.

تأكيد الإيميل مفعّل. تسجيل الدخول بكلمة مرور أو رابط يطلبه المستخدم بنفسه. الجلسات HttpOnly وSameSite مع Secure على HTTPS. يستخدم Next 16 ملف `proxy.ts` لتحديث الجلسات، والفحص النهائي في الخادم وقاعدة البيانات. تفاصيل الاستضافة في [DEPLOYMENT.md](docs/DEPLOYMENT.md).

## الفحوص

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm run test:ui
node scripts/portal-browser-check.mjs
node scripts/check-browser-bundle.mjs
```

`test:ui` يتطلب تشغيل الخادم المحلي، ويستخدم Edge في Windows أو Chromium في الأنظمة الأخرى (`npx playwright install chromium` عند الحاجة). ينشئ بيانات اصطناعية محلية؛ لا يرسل رسائل. لقطات المراجعة تحت `artifacts/screenshots`.

اختبارات الوحدة تستخدم PostgreSQL حقيقيًا، أدوارًا وصلاحيات RLS، واختبارًا يغلق القاعدة الملفية ويفتحها للتحقق من الحفظ. تم أيضًا اختبار Supabase المستضاف بحسابات اصطناعية. تفاصيل النتائج والحدود في [QA.md](docs/QA.md).

## المتبقي قبل استقبال بيانات حقيقية

مراجعة واعتماد إشعار الخصوصية (`/privacy`) واستكمال هوية المشغّل وقناة التواصل ومدد الاحتفاظ، وإجراءات النسخ الاحتياطي والاسترجاع، وإعداد بريد المصادقة وحدوده للمستخدمين الحقيقيين. الحذف الحالي يزيل التعريف والبرنامج والدعوات ويلغي الربط؛ يبقي سجلًا ماليًا مجهّلًا وسجل التدقيق ولا يحذف حساب Supabase Auth نفسه أو بيانات مدرب آخر. حذف حساب Auth بالكامل إجراء إدارة منفصل يحتاج سياسة معتمدة.

`db pull` يحتاج Docker/Podman، غير متوفرين على جهاز التنفيذ؛ حُفظ جرد المخطط الفارغ قبل الهجرات تحت `supabase/baseline`. لم تُستخدم عمليات إسقاط أو حذف على بيانات سابقة. لم تكن أدوات Supabase MCP متاحة في جلسة Codex هذه؛ استُخدم CLI للتحقق الفعلي. لا ندّعي فحص سجلات Auth/Postgres التاريخية أو تفسير «9 أخطاء» دون الوصول إليها؛ راجع [QA.md](docs/QA.md).
