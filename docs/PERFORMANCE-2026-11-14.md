# تحسين أداء EasyCoach — 14 نوفمبر 2026

## البيئة والمنهج

المشروع Next.js 16.4.5 App Router وReact 19.3، مستضاف على Vercel، مع Supabase/PostgreSQL والمصادقة والتخزين الخاص. قاعدة Supabase في لندن. توجد خدمات Paylink ورفع فيديو قابل للاستئناف وPWA. لم تُضف خدمة أو مكتبة جديدة. جرى اتباع دليل lazy-loading المرفق مع نسخة Next المثبتة.

قورنت ملفات JavaScript من بناء Webpack للإنتاج قبل تحسينات الأداء وبعدها، بعد الاحتفاظ بإصلاحات QA السابقة. القياس يجمع الأجزاء المذكورة في client-reference manifest لكل من Workspace وTrainee؛ يستثني أجزاء إطار العمل المشتركة والأجزاء المؤجلة. gzip محسوب محليًا، وليس تسجيلًا لحجم نقل CDN. فتح المحرر أو المكتبة يحمّل أجزاء إضافية بحسب الحاجة؛ ليست هذه أرقام إجمالي كل وظائف المنصة.

## الأسباب المثبتة والتغييرات

- كانت Workspace تستورد المحرر والمكتبة والإعدادات والاستيراد والمتابعة معًا. فُصلت باستخدام `next/dynamic` داخل مكوّن العميل مع الاحتفاظ بـSSR. تظهر هياكل انتظار للأدوات المؤجلة، ويبقى محتوى الصفحة الأساسي مرسومًا من الخادم. بقيت البنية الحالية دون إعادة كتابة أو Microservices.
- كانت تبويبات المكتبة المخفية تركّب محتواها. أصبحت تركّب بعد أول زيارة فقط، وتحتفظ بالحالة بعد ذلك لحماية الاختيارات والمسودات. نُقلت عمليات تحويل تمارين المكتبة إلى جزئها المؤجل حتى لا تعيد سحب بيانات الكتالوج إلى Workspace.
- أصبحت صور التمارين وفيديوهاتها تُركّب عند فتح تفاصيل التمرين؛ القائمة والأسماء والأيام والملاحظات تظهر مباشرة. فُصلت شيفرة العرض والتسجيل وصور التقدم، ولا يُحمّل مولد QR إلا عند طلب الرفع من الجوال. لا يؤجَّل المحتوى الرئيسي أعلى الصفحة.
- أثبت تسجيل الشبكة أن حفظ رسالة يتبعه GET إضافي لـRSC يعيد تحميل snapshot كاملة بعد أن أعاد Server Action بيانات الصفحة المحدثة بالفعل. أزيل `router.refresh()` الإضافي من هذا المسار؛ تبقى callbacks تحديث البوابات التي تجلب حالتها من العميل.
- كانت snapshot الرئيسية تحجب بدء قراءات المواعيد والموافقات والهوية البصرية. تبدأ الآن بالتوازي بعد التحقق من المستخدم. عند إنشاء ملف مستخدم جديد تعاد القراءات حتى لا تستعمل نتائج سابقة للإنشاء. تبقى القراءات تحت RLS وعميل Supabase المشترك داخل الطلب فقط، دون cache مشترك للبيانات الخاصة. يظل فحص صلاحية المتدرب قائمًا.

اختُبرت صفحة `/login` ببناء Production محلي، بعينة باردة ثم متكررة لكل حجم. الجوال: 390×844، تأخير 150ms، تنزيل 200KB/s ورفع 93.75KB/s، وإبطاء CPU أربع مرات. سطح المكتب: 1440×900 دون إبطاء. حُجبت Service Workers في القياس.

|---|---:|---:|
| سطح المكتب، أول زيارة | 592ms | 812ms |

هذه عينات منفردة تتأثر ببدء الخادم وحمل الجهاز؛ **لا تثبت تسارع صفحة الدخول**، التي لم تكن هدف فصل أدوات المدرب. CLS بقي 0 على سطح المكتب، و0.0121 في أول زيارة جوال ثم 0 في المتكررة. تتضمن بيانات JSON أيضًا TTFB وحجم النقل والطلبات.

قيس `https://easycoach.space/login` قبل النشر قراءةً فقط: LCP أول/متكرر 4,240/580ms لسطح المكتب و2,176/420ms للجوال البطيء؛ CLS كان 0. هذه نتيجة البيئة المستضافة القديمة، وليست مقارنة قبل/بعد للكود الجديد أو دليل تحقيق المئين 75. لا توجد بيانات مستخدمين فعلية أو قياس INP موثوق لهذه الجلسة، ولا حساب إنتاج للاختبار داخل البوابات. قيس حجم الأجزاء الخاصة من بناء الإنتاج، واختُبرت وظائفها بحسابات اصطناعية محلية؛ لم يُفتح وضع PGlite في الإنتاج لأجل القياس.

## قاعدة البيانات والاستضافة

أظهرت `pg_stat_statements` في الإنتاج لـmanagement_snapshot عدد 544 استدعاء، متوسط 544.97ms وأقصى 7,876.76ms. وكانت متوسطات الموافقات 44.04ms، والمواعيد 34.78ms، والهوية البصرية 29.40ms. هذه إحصاءات تاريخية لاستعلامات مختلفة الأحجام، وليست قياس أثر التعديل. تقليل إعادة الجلب يمنع تكرار هذا العمل، والتوازي يقلل الانتظار المتسلسل.

رُوجعت بنية snapshot والسياسات والفهارس الموجودة، ومنها `audit_coach_time_lookup` وفهارس سجلات المتابعة والصور. صلاحية أداة SQL للقراءة رفضت تبديل الدور إلى authenticated واستدعاء `private.session_uid`، فتعذر EXPLAIN ممثل لمستخدم الإنتاج. لم تُضف فهارس تخمينية ولم تُعدّل السياسات لتجاوز القيد. تحميل سجل الحساب الكامل يبقى حدًا للتوسع ويحتاج قياسًا مصرحًا لخطة التنفيذ قبل تقسيم snapshot إلى صفحات بيانات؛ اختصار السجلات دون API تكميلي كان سيخفي بيانات حالية.

Next يقدم الأصول ذات الأسماء المشتقة من المحتوى بكاش طويل؛ صفحات المستخدم بقيت `private, no-cache, no-store`. الخطوط مستضافة بواسطة next/font مع `swap`، ولم تُغيّر سياسات الصور والوسائط الخاصة أو مسح بيانات الجهاز عند الخروج. لا يوجد cache عام جديد ولا تغيير لإبطال الكاش. إعادة التحقق عند mutations ما زالت ترسل بيانات محدثة.

يلزم التحقق في لوحة الاستضافة من قرب منطقة وظائف Vercel من قاعدة لندن، وقياس زمن RPC تحت هوية إنتاج مصرح بها. لم تتغير إعدادات المناطق، ولم تُضف خدمة مدفوعة أو وظيفة خلفية بلا دليل حاجة. لا يمكن تأكيد أن موقع تنفيذ الوظائف الحالي بعيد عن القاعدة من البيانات المتاحة.
